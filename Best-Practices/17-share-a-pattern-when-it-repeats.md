# Share a pattern when a second screen needs it

A design system is a shared set of standards for interactions that repeat. Add a pattern to it when a second screen needs the same behavior. A one-off screen stays in the product.

## When it applies

Use this when someone wants a new shared component, pattern, or rule. Brand colors, voice, and one product's screens stay in that product. See [Separate practice from product](07-separate-practice-from-product.md).

## The decision

- Describe the interaction the pattern standardizes: what the person does, what each state shows, and what the control is called.
- Add it to the shared set when more than one screen, or more than one product, will repeat that interaction.
- Leave it in the product when it exists for one screen, one campaign, or a prototype that is still changing.
- Name the pattern for the interaction, not for a vendor's component. Point readers at the current platform guideline when a platform convention matters. See [Official documentation](../Official-Documentation/README.md).
- Include the empty, loading, error, and success behavior the pattern owes. See [Design states with the main path](04-design-states-with-the-main-path.md).

## Evidence

Nielsen Norman Group, last reviewed August 27, 2026: "A design system is a complete set of standards intended to manage design at scale using reusable components and patterns." The same article says the benefit is replicability of design that will be repeated, and that a full design system is a weak near-term investment for a one-off that is still changing. Confirm the current article before you rely on it: [Design Systems 101](https://www.nngroup.com/articles/design-systems-101/).
